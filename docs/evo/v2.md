# 🐝 BeeVolt GenV2: Technical Specification

**BeeVolt GenV2** là một Metadata-driven Framework chuyên dụng để tự động hóa việc di cư (Migration) và tái cấu trúc (Refactoring) các đường ống dữ liệu từ **HiveQL** sang **Spark SQL**. Hệ thống sử dụng cơ chế **SQL Decomposition** để bóc tách logic nghiệp vụ phức tạp thành các khối Lego có thể tái sử dụng.

### 📊 Bảng Mô tả Kỹ thuật Chi tiết

| Thành phần (Phase) | Mô tả Kỹ thuật | Input (Ví dụ) | Output (Ví dụ) |
| :--- | :--- | :--- | :--- |
| **1. SQL Decomposer** | Tự động phân giải script Monolithic (hàng nghìn dòng) thành các khối xử lý cột (Pre-processing) và logic delta (SCD).[cite: 6] | Script HiveQL cũ (`com_t_mhbos_m_client.sql`) với 111 rules lồng nhau.[cite: 6] | Danh sách các file SQL nhỏ (`id_clean.sql`, `nominees.sql`) và logic Delta bóc tách.[cite: 6] |
| **2. YAML Hydrator** | Hợp nhất Metadata từ Database (Phase 1) và các mảnh SQL vừa bóc tách vào một cấu trúc Pipeline duy nhất.[cite: 5] | File YAML định nghĩa target và đường dẫn các mảnh SQL vừa bóc. | Đối tượng **PipelineConfig** (Pydantic v2) đã được nạp đầy đủ dữ liệu (Hydrated). |
| **3. Type Resolver** | Hệ thống ánh xạ kiểu dữ liệu trung gian (Canonical Mapping) giữa nhiều Dialect (MSSQL, Hive, Spark, Pentaho). | Kiểu dữ liệu gốc: `NVARCHAR(255)` hoặc `BIGINT`. | Kiểu đích: `StringType` (Spark) hoặc `STRING` (Hive) kèm logic `TRIM/NULLIF`. |
| **4. Multi-Model Generator** | Engine render code dựa trên 8 mẫu biến đổi chuẩn (Model 1-8). Tự động lắp ghép logic Pre-processing vào khung SCD.[cite: 5] | Template Model 3 (SCD1 Overwrite)[cite: 5] + Hydrated Pipeline Object. | Script Spark SQL hoàn chỉnh, modular, có khả năng chạy song song các bảng tạm.[cite: 3, 5] |

### 📥 Minh họa Input/Output (Case Study: `m21_cashmovement`)

#### **Input: Raw Metadata (`m21_cashmovement.json`)**
Dữ liệu bóc tách từ Phase 1 (Discovery):
```json
[
    { "name": "Firm", "type": "IntegerType", "nullable": false },
    { "name": "CustOrBroker", "type": "StringType", "nullable": false },
    { "name": "Amount", "type": "StringType", "nullable": false }
]
```

#### **Processing: Pipeline Configuration (`raw_m21.yaml`)**
Định nghĩa cách thức lắp ghép:
```yaml
pipeline_id: "raw_m21_cashmovement"
layer: "raw"
target:
  table_name: "m21_cashmovement"
  transformation_model: "5b" # Dùng Model 5b cho Raw[cite: 5]
  partition_keys: ["etl_dt"]
```

#### **Output: Final Spark SQL (`dml_raw_m21.sql`)**
Code được sinh ra hoàn toàn tự động với cơ chế **Auto-map**:
```sql
-- Generated by BeeVolt GenV2
INSERT OVERWRITE TABLE ${raw_schema}.m21_cashmovement 
PARTITION (etl_dt = '${batch_date}')
SELECT
    FIRM,
    NULLIF(TRIM(CustOrBroker), '') AS CUSTORBROKER, -- Auto-trimmed
    NULLIF(TRIM(Amount), '') AS AMOUNT,
    '${batch_timestamp}' AS RAW_SYS_TIME
FROM ${raw_schema}.m21_cashmovement_et;
```

### 📂 Cấu trúc Repository Khuyến nghị

```text
├── configs/                # Chứa rules về Data Type và Mapping
├── metadata/
│   ├── discovery_output/   # Kết quả Schema JSON từ Phase 1
│   └── logic/              # Các mảnh SQL bóc tách từ Monster Scripts[cite: 6]
├── pipelines/              # Tệp YAML định nghĩa cho từng bảng
├── src/
│   ├── models/             # Pydantic Models (The brain)
│   ├── generators/         # Jinja2 Engines (The muscles)
│   └── utils/              # SQL Parser & Decomposer
└── templates/              # 8 Data Transformation Models (Model 1-8)[cite: 5]
```

### 🥊 Tại sao BeeVolt GenV2 lại khác biệt?
1. **Không còn "Hard-code":** Mọi logic biến đổi cột được tách rời khỏi code engine.
2. **Xử lý được "Quái vật":** Cơ chế xẻ nhỏ script giúp migration các bảng lớn (như `m_client`) trở nên khả thi.[cite: 6]
3. **Intellectual Sparring Ready:** Framework được thiết kế để dễ dàng kiểm tra lỗi (Debuggable) nhờ hệ thống bảng tạm tường minh.
